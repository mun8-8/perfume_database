## **향수 취향 탐색 서비스 개발 계획서** 

- 제출자: 조문정(2024245075, 소프트웨어학과) - 작성일: 2026/4/13 

## **1. 사용자 서비스 흐름 (User Service Flow)** 

**1.1 서비스 개요** 

본 서비스는 사용자가 향 계열, 세부 향, 발향 시점, 보조향을 단계적으로 선택하여 자신의 향 취향을 구조적으로 탐색하고, 이에 기반한 향수 추천을 제공하는 웹 애플리케이션이다. 

## **1.2 사용자 유형** 

- 비회원 사용자 

- 테스트 및 추천 결과 조회 가능 

- 닉네임 + 조회코드로 결과 재조회 가능 

- 저장 및 비교 기능 사용 불가 

- 회원 사용자 

- 로그인 후 모든 기능 사용 가능 

- 추천 결과 저장 및 비교 기능 제공 

## **1.3 사용자 시나리오** 

- 비회원 흐름 

1. 소개 화면 진입 

2. 비회원 시작 선택 

3. 닉네임 입력 

4. 취향 테스트 진행 

5. 추천 결과 확인 

6. 조회코드 발급 

7. 재조회 시 닉네임 + 조회코드 입력 

- 회원 흐름 

1. 소개 화면 집입 

2. 로그인 (이메일/비밀번호) 

3. 취향 테스트 진행 

4. 추천 결과 확인 

5. 향수 저장 

6. 비교 기능 사용 

7. 저장 목록 확인 

## **1.4 화면 흐름도** 

소개 화면 

- ├─ 비회원 시작 → 닉네임 입력 → 테스트 → 결과 → 조회코드 발급 

- └─ 로그인 → 테스트 → 결과 → 저장/비교 → 저장 목록 

## **1.5 주요 UI 상호작용** 

- 클릭: 향 선택, 버튼 선택 

- 입력: 닉네임, 로그인 정보, 조회코드 

- 선택: 최대 2개 복수 선택 

- 결과 확인: 카드 UI 

- 비교: 테이블 UI 

## **2. 핵심 기능 및 구현 명세** 

- **2.1 기술 스택** 

- frontend – Streamlit 

- Backend/DB – Supabase(PostgreSQL + Auth) 

- 데이터 - CSV 기반 자체 데이터셋 

- 추천엔진 – Python 

## **2.2 핵심 기능** 

- 1) 인증 기능 

- 회원: 이메일/비밀번호 로그인 (Supabase Auth) 

- 비회원: 닉네임 + 조회코드 

2) 취향 테스트 기능 

- 선택 구조 향 계열: 최대 2개 세부 향: 최대 2개 발향 시점: 1개 보조향: 최대 2개 

- 구현 방식 Streamlit 단계형 페이지 session_state로 상태 유지 

- 3) 추천 기능 

- 추천 알고리즘 구조 

- 1단계: 소거법 필터링 

- 향 계열 불일치 제거 

- 세부 향 일부 일치 필터링 

- 발향 시점 일치 필터링 

- 2단계: 점수 기반 정렬 

- 향 계열 일치 

- 세부 향 일치 개수 

- 발향 시점 일치 

- 보조향 일치 

- 4) 추천 결과 출력 

- 총 5개 추천 상위 추천 3개 비교용 후보 2개 

- 출력 정보 향수명 브랜드 가격 노트 구성 분위기 설명 사용자 선택 조건과 일치 항목 

- 5) 분위기 설명 생성 

- 규칙 기반 템플릿 방식 플로럴 + 머스크 + 베이스노트 

→ “은은한 플로럴 향이 머스크와 어우러져 부드럽고 포근한 분위기를 형성합니다.” 

- 6) 저장 기능 (회원 전용) 

- 단순 저장 

- 저장 목록 조회 가능 

- 7) 비교 기능 - 최대 3개 선택 

- 세션 상태 기반 관리 

- 비교 테이블 제공 

- 8) 비회원 재조회 기능 

- 닉네임 + 조회코드 입력 

- 이전 추천 결과 조회 

## **2.3 데이터셋 전략** 

- 브랜드 약 25개 

- 향수 약 250개 이상 

- 초기 개발: 60~100개로 시작
