## **1. 데이터베이스 개요 및 핵심 아키텍처** 

## **1-1. 프로젝트 개요** 

본 프로젝트는 사용자가 자신의 향 취향을 단계적으로 탐색하고, 그 결과를 기반으로 향수를 추천받을 수 있는 DB 기반 웹 서비스이다. 기존 향수 서비스가 단순 브랜드/상품 중심 탐색에 집중했다면, 본 프로젝트는 다음 요소를 중심으로 추천을 수행한다. 

- 향 계열(Category) 

- 세부 향(Scent) 

- 발향 시점(Note Type) 

- 보조 향 계열(Additional Category) 

- 분위기(Mood) 

- “어떤 향을 좋아하는가" 그리고 동시에 "그 향이 언제 느껴지기를 원하는가"를 함께 분석하는 구조를 가진다. 

## **1-2. 핵심 추천 구조** 

추천 흐름은 다음과 같다. 

사용자 입력 -> 메인 향 선택 -> 발향 시점 선택 -> 추가 향 계열 선택 -> perfumes_notes 검색 -> 점수 계산 -> 상위 5개 추천 

## **1-3. 데이터 기준(Source of Truth)** 

본 프로젝트의 향수 데이터 기준은 Fragrantica와 Accorda를 기반으로 한다. Fragrantica와 Accorda의 향수 노트 정보, 분위기 리뷰, 향 계열 정보를 참고하여 

데이터를 정제 및 표준화하였다. 

## **1-4. 향 데이터 정규화 전략** 

향 이름은 영어 기준 canonical scent로 통일하였다. 예시: 

|예시:||
|---|---|
|원본 데이터|저장값|
|Bulgarian Rose|Rose|
|Turkish Rose|Rose|
|Rose Petals|Rose|
|패출리|Patchouli|
|파출리|Patchouli|



이를 통해, 추천 일관성 유지, SQL 검색 단순화, 중복 데이터 방지를 달성하였다.

scent_categories <-> scents 

하나의 향 계열(Category)은 여러 세부 향(Scent)을 가진다. 

## => 1:N 관계이다. 

------------------------------------------------------- 

perfumes <-> perfume_notes <-> scents 

- 하나의 향수는 여러 향을 가진다.

- M:N 관계를 perfume_notes로 해결. 

------------------------------------------------------- 

users <-> user_preference_tests 

- 사용자 1명은 여러 번 취향 테스트 가능.

------------------------------------------------------- 

recommendation_results

## **6. 마무리** 

본 프로젝트는 단순히 향수 상품을 나열하는 서비스가 아니라, 사용자의 향 취향을 구조적으로 분석하고 데이터 기반으로 추천하는 향수 탐색 플랫폼 구축을 목표로 하였다. 특히 기존 향수 추천 서비스와 달리, 

- 향 자체(Scent) 

- 향 계열(Category) 

- 발향 시점(Note Type) 

- 추가 선호 계열 

- 분위기(Mood) 

다양한 선택지를 함께 고려하는 다층적 추천 구조를 설계하였다는 점에서 차별성을 가진다. 

데이터베이스 설계 과정에서는 향수 데이터의 중복과 표현 불일치를 해결하기 위해 scent dictionary 기반 정규화를 수행하였으며, perfume_notes 중심의 M:N 구조를 통해 향수와 향 데이터를 효율적으로 연결하였다. 또한 사용자 테스트 기록, 추천 결과 저장, 북마크 기능 등을 포함하여 실제 서비스 확장을 고려한 구조로 설계하였다. 

향후 확장 방향으로는 다음 기능들을 고려할 수 있다. 

- 사용자 리뷰 기반 추천 정확도 개선 

- AI 기반 유사 향수 추천 

- 계절/날씨 기반 추천 시스템 

- 사용자 취향 학습 기능 

- 향수 이미지 및 브랜드 상세 페이지 연동 

- 추천 알고리즘 고도화(가중치 동적 조정) 

또한 현재는 약 50개의 대표 향수를 기준으로 초기 데이터를 구축하지만, 이후 더 많은 향수 데이터를 추가하여 추천 다양성과 정확도를 높일 수 있다. 

본 프로젝트를 통해 데이터 정규화, 관계형 데이터베이스 설계, 추천 시스템 구조 설계, 그리고 Streamlit-Supabase 연동까지 실제 서비스 구축 흐름을 경험할 수 있었으며, 사용자 취향 데이터를 기반으로 한 추천 시스템 설계의 중요성을 이해할 수 있었다.
